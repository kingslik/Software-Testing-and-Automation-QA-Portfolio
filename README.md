# Software-Testing-and-Automation-QA-Portfolio

How can I ensure that my code, program, or software is functional and secure?
I apply testing techniques to break my code and find out whether it really works properly. Humans cannot create anything that is entirely correct since all people have mistakes, and this principle applies to software as well. Not only do I test to make sure that some feature works fine in the ideal circumstances; I try to break the code by using incorrect data, null values, or other methods to find out potential defects. Being an IT specialist, I understand that there are numerous consequences of skipping the QA phase due to the lack of time. Not using unit tests to get rid of defects will mean asking the end-user to discover mistakes made by the programmer.

How do I interpret user needs and incorporate them into a program?
I convert these demands into rigid technical limitations. If some requirement states that the number of digits in the phone number should be precisely 10, I understand that it is an absolute condition. At first, I create the tests based on these requirements without writing any code. Such a technique allows me to remove developer bias and force me to implement what the user wants in the most precise way possible.

How do I approach designing software?
I pay special attention to the efficiency and safe failure of the system. The first step before the development process is data structures evaluation. For example, keeping records in a HashMap instead of an ArrayList makes it possible to access particular record with the help of ID immediately. Also, I try to throw exceptions when the input data are incorrect and not accept this data to keep the software safe.
